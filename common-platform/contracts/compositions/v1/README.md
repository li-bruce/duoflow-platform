# 组合业务协议 1.0

组合定义引用模块已登记的公开业务流。当前支持有序步骤、明确字段连接、人工办理等待和执行前确认。模块继续决定正式状态，平台保存组合执行进度。

## 定义

- `id`、`version`、`title`、`description`：组合身份及说明。已保存版本保持不变，修改内容要使用新版本。
- `input_schema`：开始办理时填写的具名字段，使用本地明确类型。字段引用不加载远程文档。
- `steps`：最多 20 个有序步骤。每步固定模块、公开业务流及版本。
- `bindings`：目标输入字段对应 `input`、前面步骤的 `step` 输出或 `literal` 固定内容。`path` 为明确属性名数组，不能执行表达式。
- `roles`：一个组合角色可以列出多个模块的原有角色及各自范围。保存这份说明不授予任何用户权限。

平台保存时检查入口、版本、必填输入、字段类型和范围、数据读取接口以及角色声明。每次调用还需要通过当前身份、范围和模块内部对象判断。静态检查通过不能证明用户对某个尚未选择的对象有访问权。

## 部分流程

模块先在 `flow-exports` 公开明确的入口。共享流程用 `completed_states` 声明本入口的完成条件，如“提交完成”；完整流程可使用另一个公开编号并以“审核完成”为结束条件。平台读取正式对象状态，个人页面位置不会触发下一步。

## 数据传递

公开接口的数据类型必须相容，运行时再次检查实际值。业务对象通过 `projection.object_ref` 和已登记的 `read` 操作重新授权。传递前来源内容变化时停止，保留原调用记录供检查。页面读取已完成步骤时显示当前允许读取的对象内容；办理时的完成边界记录独立保存。

必填目标只能连接必定存在的来源字段，包含路径上的每一层。可选目标允许来源留空，平台省略该字段；明确填写的 `null` 仍按目标类型校验。布尔形式等当前无法确定类型的字段声明会在保存连接时被拒绝。

不含业务对象的计算结果按原调用记录及当前权限核验。复杂结构转换应由模块公开适配功能，再将该功能作为单独步骤连接。

## 执行与恢复

组合定义、运行和步骤分别存储。执行前保存输入和派发标识；实际调用继续使用统一 `Runtime.invoke`，同步和后台执行前均复查来源及当前权限。后台协调器可以在页面关闭后继续运行。

- `confirming`：等待用户确认当前步骤及对应版本。
- `waiting`：等待共享流程的正式业务状态满足完成条件。
- `waiting_run`：等待统一后台任务返回。
- `waiting_service`：读取或派发前检测到服务暂时不可用，保留当前步骤，连接恢复后继续检查。授权撤销、停用或声明改变仍停止办理。
- `succeeded`：已保存该步骤结果。
- `unknown`：已有派发记录，尚无确定结果。只核对原调用凭据，不自动重发。
- `blocked`、`failed`：暂停后续步骤，展示可处理的原因。

刷新页面、读取记录和切换到对话均只恢复引用。对话分支继续引用同一组合运行；开始新的办理需明确创建新的运行。跨服务调用没有统一数据库事务：已成功的前一步保持成功，后一步失败不会自动撤销前一步效果。

接口位于 `/api/v1/compositions`；入口见 `app/composition_routes.py`，类型和连接检查见 `app/composition_contract.py`，执行见 `app/composition_execution.py`。输入、定义、结果均属于创建者；普通管理员身份不能越过所属关系读取个人业务内容。

组合输入的 pattern 仅能复用当前所选模块已登记的输入输出格式约束，不能在组合中加入新的正则表达式。字段转换通过具名模块能力实现。
