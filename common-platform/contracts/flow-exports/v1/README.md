# 公开业务流 1.0

模块在 `backend/flow-exports.json` 中列出可独立使用、可参与组合的业务入口。`id` 和 `version` 标识这个公开边界；`entry` 指向实际能力或共享流程，`node_ids` 把入口放回模块业务图。

| 入口 | 输入与输出 | 完成条件 |
| --- | --- | --- |
| capability | 直接采用 manifest 中对应能力的输入输出 | 实际调用成功；后台调用等待 Run 完成 |
| workflow | 可选 `object_id` 选择已有对象；输出采用读取能力的输出结构 | 重新读取的正式状态进入 `completed_states` |

一次能力调用可以完成模块内部的多个业务步骤，具体过程由模块实现。需要复用部分业务时，模块提供对应能力入口，或公开共享流程的明确完成边界。平台根据声明调用和等待，模块内的正式状态仍由业务服务判断。

`required_permissions` 必须等于入口实际要求的权限。共享流程的入口要求读取权限，后续动作分别核验自己的权限；完整业务可能由不同人员参与。`data_access` 列出已注册对象的公开操作，平台不能根据角色名称推断跨模块权限，也不能直接操作模块数据库。

`resolved_flows` 从 manifest、权限附件和数据对象声明中取得输入输出、角色建议及数据接口，避免维护互相漂移的第二份接口。角色建议用于理解职责，实际授权由平台授权记录和模块对象事实共同决定。

修改入口、版本、权限或数据操作需要重新校验和接入。已保存的组合应固定这些版本；运行中声明发生变化时停止继续调用并提示重新检查。
