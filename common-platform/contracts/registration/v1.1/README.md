# 模块接入 1.1

1.1 在 1.0 的能力、数据、权限与共享界面检查上增加三项必备附件：

| 附件 | 内容 | 接入时核对 |
| --- | --- | --- |
| module_graph | 原子组件、事件、业务节点、状态和映射 | 原子覆盖实际后端函数与共享组件，事件绑定实际能力和版本 |
| flow_exports | 公开业务入口、完成边界、数据操作和入口权限 | 引用实际能力或共享流程，完成状态属于正式状态图 |
| runtime_sync | 运行事件 1.0、callback、call_ticket | 模块主动回调平台，平台确认挑战已收到 |

服务的 `GET /platform/v1/module-graph`、`GET /platform/v1/flow-exports` 与注册附件须完全一致，且与其他服务接口一样要求服务凭据。主平台对上述接口进行实际读取与未认证拒绝检查。共享前端代码与权限定义仍须由管理员安装，握手只检查已安装内容。

平台发送完整 manifest、registration、随机 nonce 和契约摘要。1.1 另外发送短时 `runtime_probe: {ticket, nonce}`。模块 SDK 对照本地完整声明、真实函数表及支持的协议，再把挑战发送到部署配置指定的运行同步地址。平台核验实际收到的回调，模块确认中同时返回 atomic_bindings 和 runtime_callback 检查结果。挑战不调用业务函数，也不创建用户授权。

模块运行同步地址为 `PLATFORM_OBSERVATION_URL`，路径 `/api/v1/runtime-observations/events`。Node 模板缺省采用已配置的中央权限地址所在平台；可以通过环境变量指定部署地址。握手使用同一地址的 `/probe` 接口。请求参数不能改变回传目标。

七类接入检查仍全部必需，结果收据继续使用收据版本 1.0。连接或契约改变、复验失败、共享组件或权限定义失配，都会阻止发布或使旧验收失效。1.0 服务保留原有行为和验收标准；只有通过 1.1 的远程服务进入新的原子和公开业务目录。

新协议要求每个公开能力对应独立权限，通用字符串命令需要拆成明确的公开能力编号。角色名称在各模块自己的命名空间内使用，注册角色模板不会替用户授权。
