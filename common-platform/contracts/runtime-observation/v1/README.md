# 运行观察 1.0

模块沿用自己的业务代码和事务。运行观察报告实际发生的调用与正式状态，读取时仍检查当前用户与对象权限。

| 标识 | 作用 |
| --- | --- |
| request_id | 主平台发起的一次能力调用 |
| atom_id | 模块已登记的后端原子 |
| call_id / parent_call_id | 本次调用及内部调用关系 |
| sequence | 本次调用内的事件序号，1 至 256 |
| graph_version | 本次采用的业务图版本 |

模块通过 `POST /api/v1/runtime-observations/events` 主动提交批次。`X-DuoFlow-Observation` 是单次调用凭据，绑定用户、服务连接、当前授权和业务图，120 秒后失效。它与业务授权凭据分开，不能用于调用业务接口。每批最多 32 个事件、32 KiB；仅允许已登记原子和状态引用，事件中不传输业务输入输出、聊天文本或服务密钥。

started、succeeded、failed 表示调用阶段；state 携带模块实际提交或重新读取的正式对象状态、修订和引用。SDK 不根据按钮、导航位置或一次请求成功自行推算正式状态。Node 模板在事务返回后报告实际 projection，Python 适配通过 `ObservationSession.state` 明确接入。

平台单独保存观察记录，支持重复事件去重、乱序补收和重启后查询。同一序号出现不同事件会拒绝整批。读取结果包括缺失序号、已知丢弃数量、最新接收时间与 active/stale/complete 状态。complete 表示调用已结束；正式业务是否完成仍查看对象状态和公开流程的完成条件。

SDK 使用有上限的后台队列和短超时，失败最多重试一次；业务函数不等待观察事件送达。未收到或过期的观察显示缺失或过期，不能据此推断业务失败。历史观察只对原调用者开放，重新校验当前身份、连接与授权；包含正式状态的记录还要重新核验对象读取权限。

前端组件观察采用独立的 `/api/v1/atomic-instances/{kind}/{instance_id}` 接口。读取沿用实际共享宿主的归属与权限；presence 写入需要登录、CSRF 和当前修订。浏览器仅报告 ready/editing/busy/error，标记为界面状态。页面与对话使用同一组件定义；浏览器会话、保存的草稿、个人步骤和正式对象状态各自可辨。
