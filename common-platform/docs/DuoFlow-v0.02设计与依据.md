# DuoFlow v0.02 模块与组合业务设计

状态：设计阶段，实施进度见项目根 ITERATION_WORKSHEET.md。用户已选择 observe，微服务继续执行自身业务逻辑；状态图关联声明、当前状态和实际运行证据。

## 采用的结构

组件定义、业务节点、组件实例、业务对象和一次调用分别有身份。一个组件可以映射多个业务节点，也可以在多个业务流中复用。映射是多对多关联；定义版本固定后，运行记录携带相应版本，避免用升级后的图解释旧记录。

原子登记描述前端输入、输出、局部状态、交互事件、调用动作和业务节点；后端动作继续引用真实 manifest 能力。业务流公开可以复用的入口与步骤，裁剪部分流程时声明新的公开子流程及其前置条件、输入输出和权限，保留原模块执行逻辑。主平台不从图中任意摘取私有函数。

图分为声明结构和运行覆盖两部分。组件的加载、输入和等待状态属于界面；对象状态来自模块仓储；调用状态来自执行回执。远端主动上报只有观察作用，不改变正式业务或提升授权。运行记录使用实例/调用/父调用或前因标识，避免把跨进程到达顺序当成调用顺序。

## 权限和数据分工

采用共同身份和独立业务权限：平台管理用户与授予记录，模块定义具名权限、范围字段和角色模板，并用真实对象事实做最终检查。模块可以附加本地业务限制；两端均允许才能执行。注册只建立定义，不授予任何用户权限。

复合应用声明每一步所需的模块权限和范围对应；组合角色是这些具名要求的显式集合，不能按“管理员”“审核员”等同名角色自动融合。既有模块角色和授权继续有效。平台预检帮助用户发现缺项，每次调用及提交仍重新检查当前授权，撤权后阻止后续写入。

数据保留在各模块，通过公开查询/命令传递允许的字段或对象引用。字段连接需有明确来源、目标和 Schema；跨模块传递不能扩大组织/项目范围。读取源数据和写入目标数据都需要当前权限。中间结果与运行图只对获授权主体可见，禁止把任意正文或凭据混入遥测。

## 执行和对话

组合定义是版本化的公开步骤与数据连接。运行另有持久编号和逐步回执。界面和对话打开同一运行，业务动作通过既有 Runtime 执行；提交前确认输入，重复提交复用请求身份。未确定结果、等待输入、失败和完成分别呈现，恢复不重放已成功业务动作。

对话结构负责选择业务、收集输入、打开对应组件及解释当前状态。自然语言建议不构成授权；后端依据注册声明和实际身份执行。确定性入口保持可用，外部模型测试是否执行单独记录。

## 检索依据与取舍

- [W3C SCXML](https://www.w3.org/TR/scxml/)区分状态、事件、转换和数据模型。本轮借鉴这些边界；用户选择 observe，因此不把图渲染器改成业务执行器。
- [AsyncAPI 文档结构](https://www.asyncapi.com/docs/concepts/asyncapi-document/structure)分别定义消息、操作、回复和安全要求。运行同步采用明确事件/接收端/身份契约，避免仅给组件编号而缺少交互语义。
- [OpenTelemetry Traces](https://opentelemetry.io/docs/concepts/signals/traces/)用 span、上下文、事件与 links 表达实际操作及因果关系。DuoFlow 需要额外保留业务节点、组件实例和正式对象引用；通用 trace 不能独自表达业务是否完成。
- [OpenFGA Roles and Permissions](https://openfga.dev/docs/modeling/roles-and-permissions)将应用检查放在具体对象权限上，角色可独立调整。这支持模块权限命名空间和显式组合映射，现有 access v1 可以继续使用，无需本轮更换权限引擎。
- [Temporal Workflow Execution](https://docs.temporal.io/workflow-execution)将持久执行与事件历史结合。借鉴逐步记录和恢复边界；本轮保留既有 Runtime 与 SQLite 本地运行方式，实施范围与生产分布式保证分别记录。

以上是方案依据，不能作为本仓库已经实现相应能力的证明。结构校验、代码映射、独立业务预期、实际运行和浏览器验收分别提供证据。
