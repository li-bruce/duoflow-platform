# 模块模板使用手册

这套模板让开发者主要维护业务函数或对象、动作、职责状态和共享组件。登录、真实用户授权、页面/对话宿主、私人草稿和继续办理沿用平台。已有独立服务可以保留原有算法和数据库，增加薄适配层。

本手册提供完整的模板操作说明；[交互式框架全貌](/#developer-guide) 讲清主框架与模块的构造、分工和交互规则。手册由平台统一 Markdown 渲染器呈现，模块模板不附带另一份独立登录页面。

## 1. 先选合适的起点

| 需求 | 起点 | 当前交付 |
| --- | --- | --- |
| 输入一段内容，执行一次，立即查看结果 | `tool-python` | 原生 Python 工具，文本整理参考；页面和对话共用 `Component.tsx` |
| 一个正式对象由不同职责持续办理 | `workflow-node` | Node 24 远程流程，创建、编辑、提交、非作者审核参考；页面和对话共用 `steps.tsx` |
| 已有 Python/FastAPI 业务服务要接入流程 | `workflow-python-remote` 适配布局 | 保留原服务，复制 Python 远程授权 SDK，补 workflow 对象适配与共享前端；支持 check，不提供一键生成器 |

本轮实际生成的是前两种组合。Python 也可持有正式流程对象；开发者可在本地仓库阅读 `common-platform/templates/workflow-module/README.md`，作为原生流程的高级参考。该文件不属于公开 Web 手册，不能把表中两种参考误解为框架的语言限制。

示例记录使用明确的 `draft → submitted → approved` 状态机；它不是通用业务审批引擎。更复杂流程应在业务层增加状态、转换条件和测试，再更新声明。

## 2. 生成并检查一个新包

在 `common-platform` 根目录、已安装依赖的环境中运行。`交付目录` 必须是已存在的父目录，两个目标子目录必须尚不存在。

```powershell
.\.venv\Scripts\python.exe scripts/module_kit.py scaffold --template tool-python --module-id sample.text --title "文本整理" --output <交付目录>/text-tool
.\.venv\Scripts\python.exe scripts/module_kit.py scaffold --template workflow-node --module-id sample.review --title "记录办理" --output <交付目录>/record-workflow
.\.venv\Scripts\python.exe scripts/module_kit.py check <交付目录>/text-tool
.\.venv\Scripts\python.exe scripts/module_kit.py check <交付目录>/record-workflow
```

尖括号内容需替换为实际路径。`--module-id` 使用独立的小写命名空间，不能占用 `core` 或其他模块的子空间。默认安装目录名把点变成短横线，也可用 `--pack-name` 指定。标题使用普通文字，不含引号、代码括号或换行。

生成器不覆盖目录，不启动服务，不改安装清单，不分配用户权限。检查器只读，使用框架当前真实校验器核验 manifest/access/flow/interaction，并检查能力版本、权限映射、对象 provider、动作、办理视图、步骤、SDK副本和安装必需文件。TypeScript AST 检查实际导出，不执行供应商源码。流程必须显式导出对象字面量 `stepComponents`，不支持动态键、展开或动态注册。

检查成功表示这些静态契约相互一致；它不证明仓储授权正确、服务已安装、复杂组件类型检查通过或生产浏览器已验收。

## 3. 开发者主要修改哪些文件

```text
module-kit.json
backend/
  manifest.json
  access-definition.json
  business.py 或 business.mjs
  handlers.py 或 server.mjs
frontend/
  interaction.json + Component.tsx
  或 flow.json + steps.tsx
sdk/python/ 或 sdk/node/
tests/
README.md
```

| 修改内容 | 所在位置 | 必须保持的约束 |
| --- | --- | --- |
| 输入字段、实际计算与输出 | `backend/business.*`、manifest Schema | 输出与 Schema 一致，不能在普通输入中接收密钥 |
| 对象与状态动作 | 流程的 `business.mjs` 或现有仓储适配 | 业务库是真源；当前状态、修订与幂等须在同一事务保护 |
| 谁能办理哪些范围 | `access-definition.json` | 权限和角色模板属于本模块；真实用户 grant 由管理者另行分配 |
| 页面与对话的操作 | `frontend` | 使用宿主 SDK；不携带服务地址、令牌、用户身份或自己的聊天系统 |
| 能力、动作、视图之间的连接 | manifest、interaction/flow、access | 修改后运行 check，所有引用与版本必须一致 |

每个具体 workflow 能力映射一个权限。动作的 `command_schema` 与 manifest 中 `input_schema.properties.command` 保持一致；创建只带 `command`，已有对象操作带 `object_id`、`expected_revision`、`command`。有需要可按当前契约设计额外只读能力，但不能把未知子命令映射回默认权限。

Python 原生 SDK 生成到 `sdk/python/module_kit.py`，同时复制为 `backend/_module_kit.py`；check 会核对两份字节一致，安装时复制整个 backend 即可。不要只改其中一份。

## 4. 先独立运行，再安装到平台

### 简单工具

```powershell
python <生成包>/tests/self_test.py
```

这会执行合成业务与授权边界测试，不需要账号或服务器。独立测试中的授权替身仅用于测试边界，生产 handler 必须使用真实 `ctx.access`。未注册权限、无 grant、缺少组织或范围不符均拒绝，不回退到全局 researcher、curator 或管理员角色。

受控安装时，把 backend 复制到 `extensions/<pack>/`，将 pack 加入 `extensions/installed.json`；把 frontend 复制到 `components/packs/<pack>/`，将 pack 加入 `components/installed.json`。保留已有清单项。重建前端并重启后端，然后由有权限的管理者授予 `<module-id>.user` 和明确 `organization_id` 范围。安装不会自动授予权限。

页面入口为共享组件目录；对话可显式打开 `/component <module-id>.tool`。继续原私人内容要恢复原实例 ID。该简单工具没有正式 workflow 对象，不虚构“我的业务”待办。

### Node 流程参考

需要 Node.js 24，使用内置 HTTP 和 SQLite，不需 npm 安装。先执行：

```powershell
node --test <生成包>/tests/workflow.test.mjs
```

独立测试会临时启动回环 HTTP 与临时 SQLite，中央决策用显式测试替身。主平台集成测试另走真实中央 AccessBridge，二者不能混称。

部署者先在私有配置中提供下列进程环境，再从生成包根目录运行 `node backend/server.mjs`：

| 配置项 | 用途 |
| --- | --- |
| `PLATFORM_SERVICE_TOKEN` | 已管理的服务端 Bearer 密钥，不写在仓库、前端或普通业务输入中 |
| `PLATFORM_ACCESS_DECISION_URL` | 固定中央决策地址，路径为 `/api/v1/access/remote-decisions` |
| `SERVICE_DATA_DIR` | 此模块独立 SQLite 目录，不指向原生产业务库 |
| `MODULE_PROJECTS_FILE` | 服务端确认的项目、机构关系文件；参考格式见 `backend/projects.example.json` |
| `PORT` | 指定回环端口；`0` 由系统选择空闲端口，启动回执会报告端口 |

示例项目文件只含合成值。浏览器提交的项目编号用于查询这份仓库，不直接变成组织事实。参考服务只监听回环地址；需要独立远程部署时由部署方提供受控 HTTPS 入口、凭据保管和网络策略。

平台接入顺序是：**发现并保持禁用 → 安装 frontend 到 flows/packs 并重建前端 → 注册 access 附件 → 启用模块 → 授予有范围权限**。发现 manifest 不会安装共享前端。所有流程能力需要宿主工作线程处理后台 invoke；返回排队回执不等于对象已经变更。

角色 `.author` 和 `.reviewer` 都要求完整的 `project_id` 与 `organization_id`。同一已授权项目内可读取协作记录；只有作者可编辑/提交，非作者才可审核，兼任两个角色也不能自审。若业务需要隐藏同项目其他人的草稿，应设计独立读取权限/事实和相应查询，不能只隐藏前端行。

页面从步骤工作台进入，对话可 `/flow <module-id>.workflow`。有权限的流程与目录会进入“我的业务”；跨人接手使用自己的私人流程读取同一正式对象。分支复制个人草稿和导航，不复制、回滚或重放正式业务。

## 5. 逐步适配已有 Python/FastAPI 服务

保留现有专业算法、业务库、原事务和独立 Web。先用新模块 ID 和隔离演示库完成接入，再评估真实迁移；不要为了使用模板把 Python 服务改写为 Node。

1. 为旧函数增加明确的能力输入/输出 Schema，生成符合 manifest 1.2 的声明和独立 access 附件。
2. 从业务仓储读取对象真实的项目、机构、所有者及状态；客户端只提交可查找的对象编号。
3. 复制 `sdk/python/remote_access.py`，使用下方接口；删除新适配路由对旧固定角色的额外硬编码门禁，保留原独立入口的鉴权。中央授权成功不代表旧网站自动获得 SSO。
4. `backend/workflow.py` 实现授权后分页的 `objects.list`、单对象 `objects.read` 和正式命令适配，返回 workflow 1.0 的精确外壳。已有 invoke 的 workspace 要求从部署配置提供，不能要求 workflow 请求中存在 `context.workspace_id`。
5. 在原事务提交点复核授权、状态、修订和幂等；专业外部写入另做领域幂等与恢复，不用 HTTP 成功替代业务成功。
6. 增加完整共享 frontend、服务自己的 `tests/test_adapter.py` 和真实启动说明，运行 check 后交给平台联调。

```python
from sdk.python.remote_access import RemoteAccessClient, service_bearer_matches

access = RemoteAccessClient(configured_callback_url, timeout_seconds=4.0)
# 在已受控服务路由内：先验证配置好的服务凭据。
if not service_bearer_matches(authorization_header, configured_service_token):
    raise ServiceUnauthorized()

record = repository.load(object_id)
decision = await access.decide(
    ticket=access_ticket_header,
    request_id=envelope["request_id"],
    operation="objects.read",  # 普通能力调用使用 invoke
    permission="example.records.read",
    facts={"project_id": record.project_id, "organization_id": record.organization_id},
)
if not decision["allowed"]:
    raise ServiceForbidden()
```

示例中的配置、仓储及错误类由现有服务提供。`example.records.read` 是中立示例权限名，必须替换为本模块 access 附件已注册、且映射到当前操作或能力的实际权限，不能照抄或借用其他模块权限。客户端依赖 Python 3.11+ 和 httpx，不导入平台内部 app。固定地址、票据头、请求/响应限长、总超时及默认拒绝由 SDK 处理；传输层不会替服务决定哪些 facts 可信。

适配包的 `module-kit.json` 可按下例填写；模块 ID、标题和安装目录名换成本模块实际值，版本字段与当前模板一致：

```json
{
  "kit_version": "1.0.0",
  "template": "workflow-python-remote",
  "module_id": "example.records",
  "title": "记录办理",
  "pack_name": "example-records",
  "kind": "workflow",
  "runtime": "python-remote",
  "contracts": {
    "access": "1.0",
    "interaction": "1.0",
    "workflow": "1.0",
    "remote_manifest": "1.2",
    "remote_invoke": "1.1"
  }
}
```

必需路径是 backend 的 `manifest.json`、`access-definition.json`、`server.py`、`workflow.py`，frontend 的 `flow.json`、`steps.tsx`，`sdk/python/remote_access.py`、`tests/test_adapter.py` 和 `README.md`。根目录启动可用 `python -m backend.server`；若保留已有启动器，README 必须写其真实命令。开发者本地补充参考为 `common-platform/docs/module-kit-coordination.md`，不作为公开 Web 阅读的前置材料。

流程服务也可提供即时工具，例如检索表单：额外交付 `frontend/interaction.json` 与 `frontend/Component.tsx`，check 会同时验证。安装时分别注册 workflow 和 interaction 包，仍使用同一后端能力与权限；不能把远程后台查询标成仅支持本地同步能力的 workflow `draft_query`。

## 6. 哪些事情已经封装，哪些仍由业务负责

| 范围 | 提供方 | 模块开发者仍需完成 |
| --- | --- | --- |
| 登录、会话、CSRF、用户身份 | 主平台 | 不接受浏览器或模型覆盖 actor |
| 有范围 grant、撤销、职责守卫 | access v1 中央机制 | 注册正确映射，提供真实仓储 facts，先过滤再分页/计数 |
| 页面/对话共享与私人恢复 | interaction/workflow 宿主 | 保持组件、动作和版本声明一致，实际验证生产构建 |
| Node HTTP 外壳与回执参考 | 可携带 SDK | 正确业务输入/输出、可信项目库、事务与提交点授权 |
| Python 远程授权传输 | `RemoteAccessClient` | 先 Bearer 鉴权，固定部署地址，不记录或长期保存票据 |
| 状态迁移与外部副作用 | 业务模块 | 状态机、CAS、领域幂等、失败与重启恢复 |

Node SDK 的 JSON Schema 校验只覆盖参考包需要的封闭子集，不是完整 Draft 2020-12；不支持的关键字或 schema 形式的 `additionalProperties` 在启动时拒绝。需要完整 Schema 时可替换为锁定版本的成熟验证库，补反例测试。check 使用框架完整静态校验器，不能取代 SDK 启动验证。

Node 存储参考限定单进程 SQLite、最多 1000 条记录，列表每页最多 50 条，逐对象授权后返回有界摘要。大规模业务应在原仓储按完整授权范围查询，不能把多个 grant 的范围拼接。未实现的明细分页、文件或长任务返回不支持，不给出假成功。远程票据只对当前短时调用有效，不是长任务委派。

游客入口、持久通知、SSO、委派管理、多副本票据密钥治理和分布式事务仍是扩展需求。保留清晰适配位置不表示已经实现；不能添加自造配置字段宣称支持。

## 7. 交付前怎样验收

先跑生成包独立测试与 check，再在隔离平台验证：无 grant 和系统管理员不自动可用、正确范围可用、异机构/异项目拒绝、未知事实拒绝、作者不能自审、修订冲突、同请求重试不重复写、同编号不同输入拒绝、重启保留对象与回执、撤权/停用使旧票据和私人实例失效。

共享前端另做宿主 TypeScript 检查和生产构建浏览器操作：页面与对话执行同能力、实际后台回执更新、刷新恢复、多实例隔离、分支不重放、跨职责只交接正式对象。模型、真实外部系统及性能容量按独立验收范围记录，不能从模板通过推导专业效果通过。

### 本次已验证的结果与边界

2026-10-02，模板及 Python 远程 SDK 的最终测试集合 **127 项通过，耗时 18.90 秒，1 条既有 Starlette 弃用警告**：`tests/test_module_kit.py` 44 项，`templates/module-kit/sdk/python/tests/test_remote_access.py` 83 项。测试包含生成包独立子进程中的 Python 14 项和 Node 10 项，以及共享前端针对当前宿主 SDK 的 TypeScript 检查；这些已经计入 127 项，不能再次相加。

| 已验证范围 | 实际覆盖 |
| --- | --- |
| 生成与静态检查 | 两类 scaffold 与 check 命令实际运行通过；无效声明、权限映射、缺失导出及非法路径等反例被拒绝 |
| Python 原生工具与宿主 | 真实用户及机构范围、CSRF、无授权拒绝、执行结果、恢复与分支不重放、撤权后拒绝 |
| Node 流程与中央授权 | 真实回环 HTTP、SQLite 和中央 AccessBridge；创建、提交、非作者审核、自审拒绝、业务中心、授权变更、旧票据撤权、模块停用 |
| Python 远程授权 SDK | 真实 AccessBridge 的 ASGI 调用，以及范围隔离、撤权、错操作/请求编号、限时限长和故障默认拒绝 |

上述验证使用独立合成数据与临时回环服务。它们不等于新模板已在用户平台安装，也不代表现有汇交、检索服务适配或生产浏览器已经验收。生成包的 Node 独立测试使用显式中央决策替身；上表中的中央授权集成测试使用真实 AccessBridge。模型、外部业务系统、容量性能和生产页面/对话的实际操作，需要各自的验收记录。

本模板修改由主框架任务统一提交、同步生成提示词并完成最终安装和生产浏览器联调。开发者本地交接记录位于 `common-platform/docs/module-kit-coordination.md`；阅读本节即可了解本次模板验证结论，无需访问该内部文件。
# 现行注册与验收要求

远程包还必须提供 `backend/registration.json` 以及相应 Node `sdk/node/registration.mjs` 或 Python `sdk/python/registration.py`。离线 check 校验公开数据、业务步骤、权限附件与能力引用；运行中的主框架再检查身份、接口、模块主动确认和已安装的共享呈现。七项全部通过后才能发布。详细字段、升级方法及两侧职责见 [模块框架说明](模块框架说明.md)、[主框架说明](主框架说明.md) 与 [模块接入标准](../contracts/registration/v1/README.md)。历史验证计数保留原日期，不作为本轮结果。
