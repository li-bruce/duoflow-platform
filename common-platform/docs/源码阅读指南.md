# DuoFlow 源码阅读指南

先看装配入口，再看一个请求怎样经过注册、授权、执行和对象读取。业务规则集中在模块，主框架负责共同服务。

## 目录地图

| 位置 | 职责 | 建议入口 |
| --- | --- | --- |
| app/main.py | 装配数据库、身份、服务、路由和生命周期 | create_app |
| app/registry.py | 功能编号、输入输出及本地函数绑定 | Registry.register、validate、load |
| app/runtime.py | 请求身份、可用性、去重、事务与回执 | Runtime.invoke、execute |
| app/remote_services.py | 受管理连接、发现、验收、远程调用 | discover、admit、invoke |
| app/access_control.py | 定义、范围授权和基于对象事实的决策 | validate_definition、check、check_command |
| app/workflows.py | 私人流程、对象引用、动作和恢复 | get、action、begin_action、finish_action、clone_view |
| app/interactions.py | 独立组件实例与动作绑定 | Interactions |
| app/state_machines.py | 状态图结构与动作引用校验 | validate_state_machine |
| app/workflow_transport.py | 本地/远程对象、文件和任务适配 | WorkflowTransport |
| web/src/workflows/FlowHost.tsx | 页面与对话共用的步骤宿主 | 草稿保存、动作提交、恢复 |
| web/src/DevTools.tsx | 声明、状态图和有限运行观察 | StateMachineGraph、RuntimeObserver |
| extensions/framework-lab/ | 中立工作项的正式对象与事务 | create_item、command、Adapter.request |
| flows/packs/framework-lab/ | 共用步骤、动作和状态定义 | flow.json、steps.tsx |
| templates/module-kit/ | 可携带的模块模板与 SDK | blueprints、sdk/python、sdk/node |
| scripts/module_kit.py | 模块生成与只读检查 | scaffold、frontend_exports、check |
| scripts/build_duoflow_repositories.py | 两个独立源码仓库的构建 | build_platform、build_kit、validators |
| distribution/ | 模块 Skill、独立检查、发布文档和介绍页源 | module-kit、platform、site |
| tests/ | 合成业务、拒绝、恢复和接入回归 | 对应功能名的 test 文件 |

## 一次正式操作

共享组件提交明确动作和输入 → 宿主检查当前私人实例 → Runtime 重新授权并检查重复请求 → 模块检查对象范围、状态与版本 → 在事务中保存结果及回执 → 宿主重新读取对象并更新两种呈现。

读代码时分清三个值：projection.state 是模块正式业务状态，cursor 是个人查看位置，Run.status 是一次调用的运行状态。任何一个完成都不自动替代另两个完成。

## 修改顺序

新增业务优先改模块。公共接入变化先复核契约和校验器，再同步 SDK、模板、测试、文档及提示词。生成提示词和手册从规范源重建。主要函数的注释说明用途、输入来源和状态边界；格式整理不得改变授权、事务、幂等或错误处理顺序。

两仓库发布版号为 v0.01。平台保留既有实现版本 0.4.0 和各协议版本；配套关系见仓库根 COMPATIBILITY.md。
