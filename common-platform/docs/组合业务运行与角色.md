# 组合业务：使用、权限和源码结构

v0.02 支持顺序业务组合。定向检查和新会话验收覆盖两个模块实际调用、部分业务流、确认、后台任务、重启恢复、撤权、角色分组及图节点关系。页面和对话的办理、刷新与分支已经过真实浏览器验证；完整测试范围见发布仓库的 VALIDATION.md。

## 使用过程

1. 在“模块业务”检索已接入且当前有权使用的模块，选择其公开业务入口。页面和对话使用同一个共享组件。
2. 在“组合业务 → 连接业务”按顺序加入入口。每个必填字段选择“开始办理时填写”或前面步骤的明确返回字段。移动或删除步骤后重新检查连接。
3. 填写组合名称和用途，检查连接并保存。保存包含模块、接口版本、连接版本和当前完整声明摘要；修改已有定义使用新版本号。
4. 在“已保存组合”填写输入并开始。可自动执行的步骤依次调用；要求确认的功能逐步确认；需要人工办理的流程打开原模块组件并等待正式状态。
5. 在“办理记录”恢复同一运行，或进入对话继续。展开整体业务图可检索业务、状态和数据节点，点击查看前后连接。

对话使用 `/business <公开业务编号>` 打开模块入口，使用 `/compose <已保存组合ID>` 准备组合输入。解释文字只准备入口；实际操作由用户发起并通过服务端检查。当前没有经过真实外部语言模型联调。

## 完整流程与部分流程

模块在 `flow-exports.json` 为每个公开入口命名。流程入口引用原有共享 workflow，并说明 `completed_states`。例如同一模块可公开“填写并提交”和“完整办理”两个入口，分别以提交状态和最终完成状态为边界。业务函数、数据和状态仍由原服务执行和保存。

组合不会按源码行截取业务片段。需要更小的独立操作时，模块提供有明确输入输出、权限和对象规则的 capability，再登记为公开入口。

## 数据和角色

平台检查结构和明确的数据连接，模块检查实际对象的当前权限、所属范围、修订和业务状态。业务对象输出必须通过 `projection.object_ref` 对应已登记的读取接口；传递前重新读取。来源内容发生变化时停止后续调用，由用户检查新旧内容。

必填输入连接到必定存在的来源字段。可选输入可以留空，例如先打开业务组件，再选择或创建对象；明确填写的空值仍须符合字段类型。

组合角色是多个模块已有角色的具名组合，每项分别保存模块编号、角色编号及具体机构/项目范围。相同角色名称不会触发权限合并。管理员明确分配后，平台在一个事务中建立各模块的普通授权；任一项无效则整组回滚。重复分配同一份有效授权会复用已有记录。权限范围保持原有“多组任选、组内同时满足”的关系。

定义先由创建者使用。具有管理权限的创建者可以发布给具备相应模块入口权限的用户；发布定义不授权模块。每名用户开始后有自己的组合运行和私人组件实例。管理员仍需相应业务权限才能使用模块，也不能凭管理身份读取其他人的组合内容。

收回公开入口阻止其他人新建该组合的办理，已存在的个人运行按当前模块权限继续读取。撤销模块授权会停止后续调用并隐藏失权内容，历史办理状态仍可查看。

## 运行与恢复

平台后台协调器每两秒检查已接受的运行。`projection.state` 是模块正式状态；工作流 cursor 是个人位置；组合步骤状态和底层 Run 描述执行进展。界面位置、前端心跳或调用观察事件均不能替代正式完成条件。

每步在调用前保存派发标识，结果保存后才继续下一步。重复页面请求使用相同标识；刷新、对话续办和对话分支保留原运行引用。进程中断后可核对已有调用凭据；没有确定结果的写入调用不自动重发。跨服务业务没有统一回滚事务，前一步的成功效果保持独立。

读取对象或准备调用时遇到服务暂时离线，运行显示“等待服务恢复”，保留原步骤和组件。连接恢复后后台继续核对正式状态。停用服务、撤销授权或修改接口会停止办理，要求重新检查。已经发出的写入调用若结果不明确，保持“需要核对调用结果”。

当前支持有序步骤及明确字段连接。循环、任意脚本转换、通用条件分支、并行分支和自动补偿尚未加入本协议。复杂转换可以作为模块的一个独立功能接入。

如果模块已经执行而平台尚未收到响应，重启后的 interrupted 回执表示结果未知。组合停在 unknown，后续步骤等待人工核对；重复恢复请求保留原调用身份和已有步骤的结果。

## 源码地图

| 文件或目录 | 职责 |
| --- | --- |
| `contracts/compositions/v1/` | 可携带的组合定义及执行语义 |
| `app/composition_contract.py` | 有序引用、输入字段和保守类型相容检查 |
| `app/composition_models.py` | 不可变定义、个人运行和每步调用凭据 |
| `app/compositions.py` | 当前身份、模块版本、数据来源、定义公开与读取边界 |
| `app/composition_execution.py` | 顺序推进、确认、人工等待、后台等待和结果核对 |
| `app/composition_graph.py` | 业务节点、状态节点、数据节点和实时证据关联 |
| `app/composition_routes.py` | 登录和 CSRF 保护的接口 |
| `app/access_control.py` | 模块权限和整组角色授权事务 |
| `web/src/business/` | 模块公开业务目录和独立使用入口 |
| `web/src/compositions/` | 可视连接、输入、共享办理、角色与运行图 |

组合入口复用 `Runtime.invoke`、`Workflows` 和 `Interactions`。这几个原有服务保持实际调用、对象适配和两种界面的共同入口。组合引入新的持久记录，保持现有 workflow 为单模块主对象流程，不往原有 workflow 协议中添加未经支持的跨模块字段。

平台仓库包含上述运行代码；模块套件提供其公共协议和接入说明。模块开发者只需维护自身的公开入口及真实业务图，平台负责组合定义、角色分配和整体执行记录。
