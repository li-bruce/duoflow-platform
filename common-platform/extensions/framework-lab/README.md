# 中立工作项调试模块

这个模块用“填写工作项 → 提交 → 完成／退回 → 修改后再提交”检查框架接线，不包含任何领域数据。它适合跟随通用框架迁移到新项目。

## 三件事分别保存

- 模块保存正式工作项、状态、修订和办理历史，表名为 `framework_lab_items`。
- 平台保存本人页面／对话的流程位置、草稿、实例关联和分支。
- 平台的持久 Invocation 回执负责请求幂等。模块使用注入的同一个数据库事务，不自行 commit，因此工作项、审计和回执一起提交或回滚。重复同一动作键不会再次写入；使用新动作键仍要通过正式状态和修订检查。

## 同一声明用于图示和执行

`flows/packs/framework-lab/flow.json` 定义步骤、组件、动作以及 `state_machine`。后端读取同一份状态转移表，前端只提交动作，不能直接指定下一状态。`draft/submitted/returned/completed` 是正式状态；`pick/edit/inspect` 是用户当前查看的步骤，两者互不替代。调试图用于查看，改变导航位置不会提交或退回工作项。

## 安装与使用

1. 受控安装列表 `extensions/installed.json` 加入 `framework-lab`；`flows/installed.json` 加入同名包。
2. 构建前端并按平台启动脚本启动。登录后从“我的业务”打开“通用工作项实验室”，或在对话输入 `/flow framework-lab.workflow`。
3. 创建工作项，保存说明并提交。观察状态、业务修订和办理记录变化；在“处理与记录”退回，再修改、重新提交并完成。
4. 从固定页面点“在对话中继续”，恢复相同的个人实例和正式对象。另开窗口操作后用刷新读取当前状态，旧修订写入会被拒绝。

Web 与对话都加载 `steps.tsx` 中的同一组件，只通过 `@platform/workflow-sdk` 调用宿主，不另写登录、对话、网络凭据或私有状态存储。组件仅使用宿主给出的 `available` 动作，后端仍再次检查本人归属、正式状态和修订。

## 权限与适用边界

这是登录账号本人独立运行的调试样例。member、管理员及继承 member 的身份可以建立自己的工作项；管理员也不能读取或修改别人工作项。列表、单对象读取和写入统一检查 owner_id。为避免调试前额外配置授权，本样例使用平台已有身份角色与严格本人归属，没有注册业务角色包。

本人可模拟“退回”与“完成”是为了单人调试，不代表真实审批允许自审。真实多人业务需要另外声明 access v1 权限包、职责分离和对象范围。样例每位用户最多保留 200 个工作项，完整历史保存在模块表中，页面最多显示最近 40 条。分页目录绑定本人、授权修订与列表快照。未接入文件、后台任务、模型或外部服务器，不把这些功能伪装成已验证。

## 修改位置

| 要修改什么 | 位置 |
| --- | --- |
| 对象字段、状态条件、存储及动作 | 本目录 `handlers.py` |
| 后台能力、输入输出和双端目录 | 本目录 `manifest.json` |
| 步骤、前端组件映射、动作与状态图声明 | `flows/packs/framework-lab/flow.json` |
| 页面和对话共用的表单、记录和结果 | `flows/packs/framework-lab/steps.tsx` |

状态图更新必须同时通过正式动作测试，不能只修改图上的文字。测试入口为 `tests/test_framework_lab.py`，使用隔离数据库验证本人范围、真实转移、并发修订、事务回滚、幂等与恢复。
