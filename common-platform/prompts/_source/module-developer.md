## 二、先核对材料，再完成实现

先阅读需求、附录及能取得的项目说明、代码和接口资料，核实已有功能和实际运行方式。整理一份简短对照：哪些可以复用，哪些需要补实现，哪些缺少必要信息。不要凭名称推断某接口、模型代理、权限或组件已经存在。

若缺少执行真实连接所必需的地址、接口说明或访问条件，应及早提出明确问题，同时继续完成不依赖这些信息的代码、契约、合成样例与本地验证。在已授权范围内持续完成实现、必要测试和交付说明，不把每一步可逆修改都变成重复确认。没有平台源码或无法访问平台时，完成独立服务与接入材料，明确留下待联调项，不能声称已完成平台注册或双端验收。

不要将新业务名称、字段、流程或专用路由硬编码进平台核心。仅当用户明确要求框架层扩展时才修改核心；现有协议确实不足时，给出具体缺口、建议字段或接口、影响范围和验证方法，不能伪装成已受支持的功能。

## 三、选择正确的接入方式

`local` 是受信任的 Python 模块，随平台进程加载，适合直接使用平台上下文、事务与模型网关。按附录组织 manifest、Schema、handler 和说明文件，通过受控安装清单加载。已加载模块可由平台启停；安装或修改代码仍需要受控发布与重启。不要让普通用户上传任意 Python 后直接执行。

`remote` 是独立部署的 HTTP/JSON 服务，实现语言不限，不导入平台 Python 内部对象。使用固定的 manifest、health、invoke 三个接口以及服务端 Bearer 认证。管理员配置地址与凭据，发现并检查声明后发布。manifest、invoke 与 health 的协议版本按末尾附录分别管理；不要假设三者必然使用同一版本。

改造已有应用时，优先把已有处理逻辑接到一个薄适配层：明确函数或接口输入，转换为能力输出，补身份范围、幂等与错误处理。保留有价值的计算和存储实现，不为了接入强制改写全部技术栈。已有页面、自有登录与平台身份的关系要单独设计，不能假设 iframe 自动获得 SSO。

外包模块默认将业务核心和用户对话分开：统一用户对话由主框架管理，模块提供可独立验证的业务能力，也可在内部使用模型完成有明确输入输出的专业处理。独立可测不要求另造一套聊天、登录或分支系统；本地测试界面应调用同一业务核心。当前提供受控共享组件及步骤流程宿主/SDK，需在实际平台构建后联调。旧远程回显模板为 legacy，不能宣称复制它就包含所有新身份、skills 与 workspace 功能。需要持续远程智能体时，应单列任务生命周期、补充输入、取消、恢复和状态隔离需求；MCP、A2A、AG-UI、A2UI或MCP Apps均不是本框架已经接通的协议。

跨模块衔接由平台统一入口和授权机制协调，模块明确输入输出语义、固定版本、来源、范围和可重试行为。JSON字段形状相同不代表业务数据可直接互换，上游结果或 action 不构成下游授权。当前“我的业务”汇合本人流程和各模块授权目录；受控 Python 模块可在同一事务中通过明确的仓储接口交接，并保存唯一来源键和固定来源版本。拆为不同服务器时仍需独立实现事务 outbox/inbox、重试回执与最终状态查询，不能把本地同库交接称作分布式事务。原有 skill 仍是顺序指导；独立 composition 可以等待模块正式状态及后台结果，并恢复已保存调用。当前没有通用条件 DAG 或按角色自动转派私人组件。短时远程授权票据是调用内的决策通道，不是长任务委派或跨模块自动编排。业务对象的正式状态由模块保存，聊天分支不回滚或重放业务。

## 四、注册能力，也注册页面与对话入口

双端目标是共享业务交互组件、动作和业务对象：固定页面按布局组织，对话按任务动态调用、组合和更新同一组件。组件可以是包含筛选、表格、预览及局部步骤的完整交互单元；局部操作不必逐次调用模型或追加聊天消息。开发或改造时先把业务组件从网站导航、登录及页面路由中分离，保持可通过宿主上下文使用。需要专用组件时提供输入、可序列化状态、事件、动作、输出语义及版本说明；不能只交付独立页面链接作为动态组件复用。

安装在 `components/packs/` 的 React/TypeScript 组件使用宿主的 React、React DOM 与 JSX runtime，统一参加平台类型检查及前端生产构建；不要在组件目录另装一套 React。Node.js 服务端依赖与这些浏览器依赖分别管理。

对话适配层使用 CopilotKit 公开的 `v2/context` 和 `v2/headless` 呈现接口，并不另接 CopilotKit Runtime。完整 Provider 的生产初始化需要真实连接，不能以空配置或假地址替代。修改呈现层后用生产构建浏览器检验进入对话、组件动作、结果更新与刷新恢复，不能只依靠开发模式单元测试。

组件 v1 已提供独立注册定义、受控前端包安装、逐实例状态持久化和双端宿主 SDK。专用组件开发同时阅读同批生成的 `组件开发提示词.md`，其附录包含完整 Schema、TypeScript 接口、Python 原生及 Node.js HTTP 骨架。组件定义位于 components/packs，独立于微服务 manifest；远程 API 注册不等于前端组件已安装。当前安装需构建前端并重启；已支持多角色通过各自办理视图协作同一正式对象，尚无任意状态版本迁移或通用跨角色事件编排引擎。组件恢复不自动触发写入；组件名称不能代替实例 ID。

将功能拆成可描述、可验证的能力，为每项能力提供稳定 ID、版本、中文名称说明、输入输出 JSON Schema、支持角色、执行方式及两端 renderer。查询与有副作用的操作按契约分别声明。必要字段、枚举、错误条件和合成样例写入 Schema，不把权限或执行规则藏在自然语言提示里。

后端支持 JSON Schema 不等于前端能完整渲染任意 Draft 2020-12 结构；复杂嵌套、组合和动态表单需要实际验证。简单 enum 和由 const/title 构成的 oneOf 使用可见标签选择框，并保留字符串、数字、布尔及 null 的原始值类型；复杂组合仍需结构化 JSON 编辑与原 Schema 校验。`format: "textarea"` 和 `format: "model-profile"` 是平台的界面提示；`password` 仅遮蔽显示，不提供凭据保管。普通 `payload` 会进入调用历史，不能用普通表单字段接收密钥。当前未配置 `email/uri` 等 format 的格式验证，需要用 `pattern` 或显式业务校验落实相关要求。

同时声明 `surfaces.page_tools` 和 `surfaces.conversation`。页面工具引用真实存在的 capability ID，对话也引用相同能力；每项面向用户的功能都要有对应的双端入口。引导语帮助发现能力，不代替权限校验。一个漂亮页面或一段聊天回答不能替代另一端的实际功能。

多步骤功能可声明 `surfaces.conversation.skills`：稳定 ID、标题、说明、triggers、entry_capability 和 steps；第一步必须是入口能力，每步引用模块内真实能力。明确入口为 `/skill <module_id>/<skill_id>`。平台保存流程状态并展示可执行表单，业务服务返回下一步 actions 和真实对象标识；失败、权限不足和等待复核都应给出可解释状态。不要让模型自行猜测对象 ID、审批结果或已完成步骤。固定页面需要提供同一组步骤和结果入口。

当前模型的工具建议会形成用户可审阅的参数表单，由用户点击执行，尚未实现模型连续自主执行工具的循环。自动发现已注册能力不等于自动执行能力；需要自主执行时，应作为明确的框架扩展提出。

平台只向模型提供已授权且当前可用的候选能力，并限制工具数量、参数 Schema 和对话上下文大小；活跃流程优先限定到当前及相邻步骤。模型侧参数是业务 Schema 的简化投影：本地引用展开，动态对象与复杂组合以 JSON 字符串提示，返回后仅转换为待核对的表单预填值。原始注册 Schema 仍是执行校验的依据，字段投影不会放宽业务规则或权限。上传文件与已弃用字段不交给模型生成，缺失材料应由用户上传；模型生成的无效 JSON 留作待补字段，不触发执行。适配投影或合成请求成功不等于特定供应商已支持所有业务，也不证明历史模型失败的原因。

`form` 复用平台按 Schema 生成的表单与结果组件，调用后进入统一运行记录。`embedded` 显示服务自己的页面，提供基础地址下的受控路径，并关联可调用能力。独立页面中的点击不会自动保存为平台资源；需要平台执行、审核或留痕的动作，应通过关联能力完成。不要把只有页面链接的模块宣称为已经具备对话交互。

新远程 manifest 1.2 支持 `text-result`、`json` 和 `workspace` renderer。workspace 用严格数据 blocks 表达文本、表格、指标、统计图、位置示意、证据、图片、下载和下一步操作；两端共用相同组件。表格筛选只针对当前返回结果；位置示意不是已接入行政区 GIS 或空间分析引擎。只填一个新组件名称不会生成组件；超出现有结构的复杂视图需要明确扩展契约。不要在框架外另建登录或聊天入口绕过统一体系。

嵌入页需要适应 `credentialless` 及不含 `allow-same-origin` 的 sandbox。平台不向它传递登录凭据、服务令牌或模型密钥，也没有通用 SSO、跨窗口业务消息桥。不支持必要隔离能力的浏览器拒绝加载；新页面发布后可能需要刷新工作台以更新 CSP。不要通过放宽隔离来解决依赖 Cookie、父窗体或存储的问题。

## 五、按契约执行与保存结果

索引缓存和向量复用统计同样遵守可信机构、项目和用途范围；不能用跨范围缓存命中、全局词频或计数泄漏未授权来源是否存在。短请求内复用许可证明不替代输出／提交前的新授权核验。

源内容撤回、字段改密或记录删除不等于用户 grant 变化。现有身份／grant 快照只覆盖授权变化，不能替代来源生命周期检查。对需要即时撤回的知识等内容，采用仅保存不含正文的业务对象引用、共享 workflow 每次实时读取投影的模式；业务模块在读取、引用预览、导出、历史恢复和模型上下文前重新检查 source/record/version/field/projection 依赖。调用 summary、data、resource、workspace、聊天文本和私人草稿不得另外留存受限正文；分支只复制引用。若选择保存正文快照，必须另行交付可核验的源依赖协议和宿主检查，不能声称本框架已有通用源撤回代理。已经被用户阅读或自行复制的内容无法自动收回。

本地 handler 接受平台注入的 `ctx` 和已校验的 `payload`，返回 `CapabilityOutput`；`data` 符合输出 Schema，呈现数据与实际结果一致。已注册业务使用 `ctx.access.check(ctx.actor, permission, trusted_facts)` 作范围判断，再检查业务状态和修订；trusted_facts 来自模块仓储。`ctx.access_stamp` 是该次受控调用的授权快照，`ctx.create_resource` 会将其带入平台资源；不得伪造或移除快照。用 `ctx.create_resource`、`ctx.create_artifact` 保存资源及关联产物，不自行提交平台事务、不另建下载授权。ctx.create_artifact 处理 UTF-8 文本；workspace 图片与下载另以有体积上限的 base64 block 表达，不能假设已支持任意二进制大文件。

workspace 下载仍由服务按原契约返回 filename、media_type、content_base64。平台保存原结果，展示时将下载块投影为平台生成的附件链接；远程服务不得自行提供下载 URL。每次点击均重新核验当前登录身份、结果归属、授权版本及能力访问权限，返回原字节并强制附件下载，不将服务令牌或远端地址暴露给浏览器。已保存产物不依赖服务保持在线；模块停用或权限撤销仍按平台当前访问规则处理。缺少身份快照和视图授权版本的旧记录无法核验历史授权，需要重新生成。

远端接受附录规定的请求，原样回传协议、请求编号、能力编号与能力版本，返回简短 `summary` 和真实 `data`。远端响应不指定平台的 resource、views、所有者或可执行地址。平台依据 manifest 中可选的 `result` 决定资源与文本附件保存；未声明保存就不要声称创建了平台资源。字段、体积、能力数量等限额按附录执行，不用超大内联内容绕过限制。

新远程 manifest 使用 1.2，invoke 请求和响应使用 1.1；完整 JSON Schema 在附录。actor 精确字段是 id、role、roles、organization_id、team_ids、name、authorization_revision，工作空间另在 context.workspace_id。role 是主角色且必须在有效 roles 中；自定义业务角色和 permissions 不塞入 actor。模型、普通表单和浏览器不能覆盖这些字段。远端先验证服务 Bearer。尚未注册 access definition 的旧模块沿用固定 roles 与对象守卫；已注册模块使用下述中央范围授权桥接，不能仅凭旧 roles 放行，也不能在桥接失败时退回旧角色允许。

平台固定身份角色包含 researcher、contributor、curator、reviewer、system_admin；新模块的业务角色使用独立注册机制，不扩充这些身份枚举。前四者继承基础 member；system_admin 管理平台和身份，不隐式获得业务全读。旧 admin 仅保留历史示例行为，不能新增分配；不要以它代替新业务授权。机构/团队由平台维护，一个账号不能加入其他机构的团队；同机构不自动共享私有资源。workspace_id 表示共同部署空间，不是私人目录，业务必须明确本人、团队或机构的访问范围。

### 可注册权限、多角色办理与统一工作中心

身份状态、平台管理职责、模块业务角色分别建模。游客、已登录基础账号和模块参与者不能按“权限等级”简单递增；注册或登录本身不授予业务范围。当前工作台及业务 API 要求中心登录，只有管理者建号，没有自助注册、匿名业务目录或游客会话。`public_registry` 表示当前登录用户可见的目录，不是匿名接口。system_admin 不隐含业务读取，但持有 identity.manage 的中心管理者可以分配业务 grant；受范围限制的业务授权委派尚未实现。

交付“入口可发现—页面/组件可进入—数据可读取—动作可执行”访问表，覆盖页面、对话、历史、消息及附件，并区分服务不可用和权限不足。surfaces/experiences 是现行呈现和职责映射，没有通用游客开关；公开访问要求先作为设计附件交付，不把 public、guest、audience 等自造字段加入现有 manifest/flow/actor。模块一项查询公开不表示整个模块公开，公开投影与内部字段需要分离；隐藏入口、前端路由、CORS 和模型提示都不替代后台授权。

未来游客扩展使用统一匿名策略和逐访客隔离的有限期会话，不能共用 guest 用户的聊天、草稿或授权。不持久化的公开浏览可没有访客 ID；若允许匿名会话升级为登录会话，只迁移当前合法持有且允许保留的内容，轮换会话标识、重新授权，不自动重放业务动作。以上仍是待实现设计；不要将 guest 伪装成 member 绕过当前登录边界。已有 embedded 是不传平台凭据的隔离 iframe，不提供 SSO；独立模块直接 URL/API 也必须核验身份与对象权限。服务 Bearer 不等于用户权限。

开始开发时交付“职责—动作权限—对象范围—状态条件—字段投影—两端步骤”的矩阵。区分角色模板、实际授权范围和办理视图；同一正式业务状态机可对应不同职责的页面与对话路径。本人跨入口继续同一个个人实例；跨人通过正式对象和待办交接，不复制他人的私人对话或草稿。前端隐藏、只读模式、步骤游标和模型提示词都不能代替后端授权。

`contracts/access/v1` 已提供独立权限包。受控 local 模块在目录交付 `access-definition.json`，由平台加载；remote 模块交付同一附件，在发现模块后由有 `identity.manage` 的管理入口审核注册。远程顺序为发现并保持禁用、安装需要的 flow/组件、注册附件、启用、再分配实际用户授权；启用但尚无 grant 的新模块拒绝业务访问。字段为 contract_version、module_id、version、title、scope_keys、permissions、role_templates、command_mappings、experiences、workitem_sources。完整字段和限额以附录 Schema 为准，不扩充现有 manifest、flow 或 actor。每个权限、角色模板、experience 和 source 的 ID 必须以本模块 ID 加点号开头；模块命名空间不能相互包含。

模块声明业务权限、角色模板、可信对象事实和参与视图；框架统一管理实际用户授权、到期、撤销、定义修订和管理审计。角色模板的 required_scope 要求至少一个范围维度；管理者将 subject_id、module_id、role_id 与 scope 绑定，scope 不接受通配符。每条授权内所有条件同时满足，授权之间按完整范围取并集，不能跨条目拼接角色和范围。升级时旧授权保留权限快照，与新模板权限取交集；新增加的权限须另行授权。安装模块没有默认业务授权，旧 admin/system_admin 不自动取得新模块内容。当前按单个用户授权，尚无组授权、委托业务管理员或外部 OIDC 登录。

权限 guards 支持 actor_is_fact、actor_not_fact、fact_in；缺少事实默认拒绝，所有角色组合都须满足守卫。Casbin 通过框架固定模型处理完整授权，模块不能上传可执行策略表达式。`has_permission` 只决定目录可见，真实对象使用 `check`，列表使用完整 `matching_scopes` 或等价仓储过滤，先授权再分页、计数、统计及字段投影。业务状态机、事务、expected_revision、文件关联和强制职责分离仍在模块端落实。`command_mappings.command` 仅用于字符串子命令选择器；workflow v1 的结构化 command 信封应映射具体 capability，不写这个子命令字段。

`experiences` 把所需权限映射到已安装 flow_id，可选 step_ids 限定可见步骤。所有 required_permissions 均满足才出现入口；同 flow 的多个获准 experience 合并可见步骤，page_groups 同时过滤。experience 不授予动作权限，已注册模块没有匹配 experience 就不能通过旧角色进入流程。同一个人在不同项目担任不同职责时，可以为各路径提供不同 read capability，让模块根据可信对象事实返回各自目录；不要用浏览器过滤替代这个边界。只读组件和可编辑组件可以复用相同源码。

“我的业务 / 继续办理”提供 GET `/api/v1/business/catalog`、GET `/instances`、GET `/objects?flow_id=...&cursor=...&limit=...` 和 POST `/open`。以上后三个相对路径同属 `/api/v1/business`。目录列出授权办理入口；instances 返回本人可恢复的最近最多 100 个流程；objects 经该 flow 的 provider 实时调用授权 objects.list，显示标题、项目、状态与可办理动作。`workitem_sources` 当前为注册的待办来源元数据，中心不自动执行其中任意能力，也没有另建业务镜像或通用待办调度器。open 使用 instance_id 恢复本人流程，或 flow_id、可选 object_id、idempotency_key 建立本人工作台；surface 为 page/conversation。对象读取先通过模块授权；新建工作台不等于新建正式业务对象。只有明确恢复同一 instance_id 才延续同一私人草稿。

新 access 模块的调用、平台资源、个人流程、组件和生成回复使用授权快照保护历史。本人授权变化、到期、定义变化或禁用使旧快照失效；其他人的单独授权变更不应中断本人。当前是保守的整体授权快照：本人任一有效范围授权变化可能使其他已有 scoped 私人实例也需重新建立，并没有按单项目自动迁移旧草稿。新入口从模块读取正式对象，不复制其他人的私人草稿、对话或审批权。尚未注册 access 的旧模块继续现有固定角色路径，不能把兼容路径声称为已完成范围权限迁移。

远程已注册模块收到 `X-Platform-Access` 短时签名票据，invoke/actor JSON 保持不变。模块先验证原服务 Bearer，从自有仓库读取可信 facts，再由服务端调用固定配置的 POST `/api/v1/access/remote-decisions`，正文是 request_id、operation、permission、facts，票据放同名请求头。operation 必须对应此次 invoke 或 workflow 真实操作。返回 allowed、reason、policy_revision；超时、无效回复、失效票据均拒绝。票据绑定用户、模块能力、连接修订、请求和操作，不能切换上下文。它只提供当前决策，模块仍须事务内校验状态、幂等、修订和提交点。票据不可进入页面、模型、日志或业务持久化；callback URL 只来自服务端配置。Node 参考代码在附录 `templates/remote-access-client`，其他服务语言可用相同 HTTP 契约。当前默认签名密钥仅在单进程内存，未提供多 worker 共享密钥治理或长期委派。

平台在 SQLite 中维护统一身份和中心会话；角色、机构、团队、启用状态或密码变化会增加授权修订并撤销旧会话。执行前、后台执行与返回时要使用当前权限；历史内容也需重新检查，不能把旧卡片或既有下载当作永久授权。正式部署可对接成熟 OIDC 身份服务，但本轮没有实现外部 OAuth/OIDC 登录、iframe SSO 或完整生产身份治理，不应自行编写 OAuth 供应商。

小文件输入用 `format: "platform-file"` 的对象 Schema，值为 filename、media_type、content_base64，可放在顶层属性或数组 items。单文件与整体请求限额见附录。服务仍需验证真实类型、内容和业务规则；密级、公开查询与申请后交付的边界由业务执行，不能因前端能显示数据就开放批量下载。文件字节不保存在聊天表单草稿；长期对象版本和大包传输需要业务持久化与独立适配。

平台支持恢复本人历史、当前会话、消息输入草稿，以及底部主动打开的能力卡草稿；更新状态有 expected_revision。消息、流程与结果 actions 中的表单使用各自原始预填参数，当前挂载期间保留编辑，刷新后恢复原始参数，文件需重新选择。同一能力 ID 不能标识某一张表单实例，不得把一个对象或业务流程的草稿自动套给另一张卡片。旧版本主动能力卡草稿可能来源不明确，使用前应核对，必要时手动重置；平台不批量清除存量用户草稿。跨刷新恢复每个历史表单的独立修改需要后续增加稳定实例标识，不能宣称现已支持。平台也支持按指定消息位置创建分支；分支复制的是对话上下文，不回滚已发生的业务操作或远程副作用。跨用户共享、长期项目对象版本和业务成果分支需要显式业务授权与对象模型，不能只靠复制聊天记录替代。

当前 LangGraph 流程以 SQLite 持久插入顺序判断消息和调用先后，不能用可能重复的时间戳或随机 ID 排序推断完成顺序。流程记录入口前的调用游标，入口前的历史操作不会自动完成新步骤；退出流程也不能被旧卡片恢复。升级前没有顺序版本标记的流程需要重新选择入口，不自动重放业务。改用其他数据库时须实现明确的事件序列适配，不能直接宣称可多进程运行。

## 六、幂等、错误与运行状态

平台防重复提交不代替远端幂等。远端对平台传入的 `request_id` 持久保存完整请求指纹和成功响应：同编号同内容返回原结果，改变参数、能力版本或上下文返回 409。重启后仍需有效，并按部署规模处理并发。外部写入与结果缓存之间的失败窗口需要明确处理；不能用内存字典或一次成功演示宣称任意副作用“恰好一次”。

返回稳定错误码和可读说明，使用契约的 HTTP 状态与错误结构，不回显凭据、敏感正文或供应商原始错误。模型失败、超时、服务不可达与参数错误应保持可辨识，不改成空结果或预制成功。 本地 ctx.gateway.chat 可返回白名单 finish_reason（stop、length、max_tokens、tool_calls、content_filter、function_call），仅在供应商实际返回受支持值时保留；缺失不能推断完成。模块可在既有安全错误详情中分类空内容、截断、JSON 或 DSL 不合格，不能写入原始模型回复和凭据；提示中的输出根结构须与校验 Schema 一致。网络超时不等于远端没有执行，重试同一次调用时保留编号和内容。

新 invoke 1.1 将 401 保留给服务连接认证；403 表示业务操作无权，404 表示对象不存在或不可见，409 表示业务状态/版本冲突，413 表示输入过大，422 表示业务校验失败，503 表示暂不可用。409 的 `error.code` 可使用 revision_conflict、state_conflict 或 idempotency_conflict；平台只在最多 4 KiB、最多 1 秒的错误响应内识别这三个固定值并转换为自身文案，不回显远端 message/details。其他冲突保持通用提示，不把所有 409 都当成幂等错误。旧协议及发现/健康错误分类独立保留。

原 invoke 仍为一次请求—响应，平台后台等待上限以末尾附录导出的配置为准。`background` 本身不代表远端长任务协议，不接受 HTTP 202。需要长任务时使用独立 workflow adapter v1：业务能力启动任务并返回引用，宿主通过固定的 jobs.status/result/cancel 操作读取或控制业务任务；没有回调、SSE 或自动事件编排。不能把一个任务 ID 当作已完成的结果。

health 应快速、低成本地说明可用性，不执行真实业务或调用收费模型。平台后台定期探测，按失败阈值标记离线，成功后恢复；长时间没有新观测则标记过期。检查周期、单次超时、失败阈值和过期时间使用末尾附录从源码导出的值，不在模块中复制另一套默认值。注册、发布、启用和健康是不同状态；健康恢复不会自动发布新契约或撤销人工停用。当前采用平台主动探测，没有服务推送租约。

管理接口更新已有远程连接，以及启用、停用远程服务或模块时，携带管理员实际读到的严格正整数 `expected_revision`。冲突后重新读取并核对，不用最新修订自动重试旧表单。远程实际启停也递增服务修订；重复相同状态仍检查修订，但不增加代际。启停保留原心跳状态及检测时间，不能借停用/启用将离线或过期状态清除。心跳按服务与修订合并，旧配置的在途检查不更新新配置。管理 `GET /modules` 的 `registration` 只描述后端已加载的权限、流程和组件定义，不证明实际用户获权、前端生产包已安装或业务验收完成。

## 七、模型与凭据

本地模块需要模型时调用 `ctx.gateway`，按需要复用模型选择字段，使用真实返回结果并保留可解释的失败。不要在模块中复制平台密钥、另造模型连接配置或用固定文本假装模型输出。

远程服务没有平台模型代理，不能自动继承平台已配置的模型连接或 Key。若远端自身调用模型，应由用户授权并在远端安全配置凭据；若要统一代理，应明确作为框架扩展提出。服务 Bearer 与模型凭据是不同用途，不能互相替代。凭据只放受控服务端配置，不写入 manifest、Schema、页面源码、URL、日志、样例或交付文档；不读取与任务无关的密钥文件。

## 八、验证、交付与完成标准

至少验证真实处理结果、输入输出校验、权限与对象范围、幂等重放及冲突、重启恢复、错误与超时、资源和产物内容。远端还需验证三接口认证和健康；嵌入页需确认在实际隔离环境中可用且不取得平台凭据。测试隔离数据和端口，避免修改正在使用的业务数据。

取得平台访问条件后，实际注册并分别从固定页面、统一对话完成同一场景，核对结果与运行记录，而非只证明 HTTP 返回 200。依赖模型或其他服务时分别标记 stub 验证、真实接口验证和端到端验证；失败或未执行的检查如实记录。合成样例可用 `example.echo` 表达消息回显，不混入真实业务数据或凭据。

交付代码、manifest、Schema、必要测试、启动停止说明、配置项说明和接入步骤。改造项目另附变更边界、已有功能保留情况与恢复方法。用简短清单区分“已实现”“已通过实际验证”“合成或模拟验证”“待联调”和“规划扩展”，说明证据、剩余依赖及下一步。拿不到源码、地址或权限时，不虚构已经集成的界面、服务或结果。

框架与各独立微服务分别维护自己的本地 Git 仓库。完成相关检查后，在本轮授权范围内提交所属项目的改动，使用中文规范提交说明，不自动推送远程；不提交数据目录、凭据、日志和依赖。共享工作区并行开发时由统筹者统一提交框架，避免混入未完成变更。跨服务接口变化先统一更新契约、框架和受影响服务及测试，再重建本提示词；日常业务改动不随意修改公共认证和协议边界。

## 九、步骤组件、权威业务对象与适配器

多步骤业务使用同批 `组件开发提示词.md` 的 WorkflowStepProps 与 flow.json。安装的 `flows/packs/<pack>/steps.tsx` 导出具名步骤组件：固定页面组织步骤导航，对话只呈现当前步骤和文字引导；两端共用源码。流程定义独立于 manifest，不要求全量动作拥有同一种角色，provider 的 read 能力授权打开流程，各动作再逐项按角色、服务可用性和模块返回的 allowed_actions 过滤。前端只能发静态动作 ID 与合规 command，不能选择任意 URL、能力或身份。

正式业务状态及版本由一个明确模块持有；平台个人流程仅保存对象引用、UI 草稿、导航及回执引用。恢复要重新读取当前权威 projection，执行时以角色/范围/expected_revision/状态机联合裁决。平台业务 Run、业务服务 job、个人 UI 草稿、聊天导航是不同对象。接手者通过自己的账号读取被授权业务对象，不复制其他角色的私有对话；聊天分支只复制草稿与指引，不回滚对象、不重放提交/批准/发布。

Workflow action 默认通过既有 invoke 发 `{object_id,expected_revision,command}`，creates_object 只发 command。`mode:draft_query` 仅用于同步 query，不发送正式对象引用、不创建正式对象，其样例对照或模型草案输出不能作为审批证明。业务命令的幂等回执与业务修订必须原子保存；网络超时后查询当前状态并以同一请求编号安全重试。个人步骤前进不是业务成功证据。

步骤宿主可对失败的平台 Run 显式“重试原请求”，沿用原 Run、invocation 与原输入，不自动采用后续个人草稿。业务 job 的重试属于模块状态机，需要独立验证；平台 Run 启动成功与业务 job 完成是不同事件。

workflow adapter v1 的只读对象操作、上传与任务操作是固定协议，不能在旧 invoke 中随意添加字段。JSON 包络含 protocol_version/request_id/context.actor/input；响应匹配版本和 request_id。平台从已安装 provider 解析能力和对象引用，复用管理员现有服务连接与凭据，拒绝浏览器指定 URL/actor/object_ref、重定向、202 和超大/内联文件响应。文件和任务编号仍需业务服务重验范围与所属对象。

完整报告及历史保存在模块，投影、命令、上传与任务响应只带有界摘要。objects.list 按白名单 object_type、cursor、limit 分页，返回 objects/next_cursor；objects.detail 按绑定对象、模块章节 section、cursor、limit 读取明细，返回 object_ref/revision/items/next_cursor/total。游标须绑定对象、章节及一致性快照，仍需逐次授权。目录128 KiB、投影1 MiB、详情512 KiB，最终 Flow 2 MiB；不能因一条大报告使全部目录无法打开。自身类型之外的目录需要 provider.related_object_types 显式声明，不靠混合前若干条让前端猜测。

固定 Web 可由 page_groups 同时组合多个注册步骤组件，对话只呈现当前步骤；二者共享源码、正式对象和个人实例。step_actions 是当前授权动作摘要；从另一个可见组件发命令仍先正常保存草稿与切换游标，再走同一动作接口。分页结果只留在视图内存，对象或修订变化后丢弃，不复制到聊天分支。页面组合本身不增加业务权限。页面和对话宿主空闲时约每 15 秒复核可见性；403/404 或流程定义变化清除失权内容，普通网络失败保留私人草稿。此刷新用于界面更新，不能代替服务端每次请求的授权检查。宿主按实例隔离异步读取，拒绝旧响应及修订倒退；重新读取时锁定编辑并等待已发出的保存结束。目录和详情同样丢弃失效请求。

上传通道逐块最多 1 MiB，不改变既有 platform-file 单文件 4 MiB 的限制。上传会话、完整性校验、正式文件关联和业务数据校验分开，模块实施总容量/文件数/压缩包额度/失败清理和安全解析。当前分块协议本身不证明已通过 GB 级真实容量验收。正式附件用 file_ref，草稿与聊天不保存字节。任务由业务能力启动，job 才是其状态权威；取消只有执行者确认停止并未提交结果后生效，已提交的业务不能借取消回滚。

Python local 既可以提供无状态查询，也可以持有业务状态。受控 extensions manifest 的 workflow_adapter 工厂安装本地 adapter；handler 与 adapter 共享模块选定的存储和守卫，不能把同一对象分别存进两个后端各自裁决。缺少文件/任务实现应明确未支持；本地工厂不是任意用户上传 Python 的执行入口。Node 或其他 remote 通过相同 workflow HTTP adapter 对接；角色、状态机、领域字段及规则留在业务包，主框架没有业务专用分支。

现有 LangGraph 继续承担顺序指引，workflow 导航可精确触发或由模型选择步骤；它们都不是业务状态真源。框架未部署 Temporal、XState、AG-UI、MCP Apps 或通用分布式 DAG。成熟状态机可用于模块内部实现，只能有一个正式状态裁决者。若需复杂事件恢复、定时或跨模块依赖，独立设计并验证，不能仅通过声明流程图宣称已经支持。

涉及规则生成的模块应让模型产生受限可读 DSL；严格验证后用合成案例试跑、比较差异，人工批准后发布不可变版本，生产校验确定性执行。不得执行模型生成代码、脚本或任意表达式。示例使用合成数据不等于迁移真实数据库、对象存储或生产业务。

## 通用架构、状态机与开发调试台

业务事实以模块返回的 projection.state 为准，个人流程 cursor 和任务 Run.status 分开处理。workflow 可以声明 state_machine；完整 Schema 随契约附录导出。它描述业务状态、转移及 step_id/action_id 引用，校验器检查重复、起点、端点与动作关系。guard_description 仅供说明，权限和状态守卫仍由模块后端执行；不得以浏览器改状态或模型文字代替业务事务。无状态机的历史流程显示未声明，不用导航步骤冒充状态。

模块开发完成后使用 /#devtools 检查 capability / interaction / workflow 的定义、引用版本、前端安装情况与可用性。JSON 校验不安装、不执行源码、不访问网络引用；在线交互 state_schema 正则不执行，含该类规则时到离线受控校验。调试台仅平台管理员可用，且只观察本人流程和当前有权业务对象；每2秒轮询、暂停/手动刷新、图与正式 FlowHost 并排。观察历史最多100条，仅当前对象的状态元数据，不含正文与草稿，也不是完整业务事件审计。源码已安装与浏览器构建已加载分别核实。

优先用 framework-lab 中立模块演练：创建→提交→退回→修改→重提→完成，页面/对话共用步骤组件和对象。它是本人调试样例，不是允许自审的真实审批规则。Node workflow-node 模板也从共享flow状态声明执行转移；其他模块可用自有业务状态引擎，仍返回统一投影。

架构与迁移入口见 docs/通用框架架构与代码地图.md、docs/模块开发与调试说明书.md、docs/框架迁移与AI交接指南.md。scripts/export_framework.py 从正向源码清单导出全新通用包，仅安装 framework-lab，重建提示词与说明书，不复制业务数据/凭据/远程连接/行业演示账号/依赖/构建物/Git历史。新包仍需安装锁定依赖、构建并实际验收；导出摘要不是运行验收。
