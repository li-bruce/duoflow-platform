## 先准备，再实现

1. 阅读同批 `docs/模块模板使用手册.md`、`templates/module-kit/` 和 `scripts/module_kit.py --help`。需要精确协议时查询同指纹的 `模块开发与改造提示词.md`、`组件开发提示词.md` 及框架契约。没有模板包或目标框架时说明缺项，不虚构已完成接入。
2. 一次输入得到结果，选择简单工具；有正式对象、多人办理或长期状态，选择流程业务。使用当前工具支持的组合生成新目录，或按手册适配已有服务；不为适应参考示例而重写已有专业算法。
3. 主要实现四项：业务对象、业务动作与状态、职责和范围、共享界面组件。页面组合组件，对话按步骤呈现相同组件，调用同一业务后端。后端以可信仓储事实检查对象权限，不能只隐藏按钮。
4. 使用模板 SDK 接入框架身份与授权，保持当前 manifest、invoke、workflow 和 access 契约。模块角色不塞进固定 actor.roles；安装定义不自动给真实用户授权；服务端凭据不代替用户业务权限。
5. 完成模板的只读静态检查、独立运行及实际业务测试，再在受控宿主验证固定页面和对话。静态检查不执行供应商业务代码；生成包或 HTTP 200 不代表已经接入，每项操作需要核对真实结果和状态。

## 哪些交给框架

统一登录、授权管理、对话记录、私人实例恢复和分支、能力执行入口、共享组件宿主、服务注册和健康检测由框架负责。模块负责实际业务、正式对象、可信归属、并发修订、幂等和专业处理。

当前没有完整游客模式、自助注册、独立站点 SSO、受限授权委派或持久参与者通知。遇到需要这些能力的业务，明确提出公共扩展，不自行另造一套，也不写假字段宣称已经支持。

## 交付与验证

本独立平台默认使用 8030；Vite 开发代理通过服务端 `PLATFORM_BACKEND_URL` 显式选择后端，默认 `http://127.0.0.1:8030`。新模块的中央授权地址也使用本实例，不能沿用原项目的端口或运行目录。

初次了解可打开默认首页或 `/#guide` 的四步入门页。其练习仅保存在浏览器，不调用实际业务接口。模块正式验收使用需要登录的工作台与对话入口；不要以教学练习替代两端宿主与后端规则测试。

交付可复制模块包、运行方式、权限及安装说明、测试证据和一份简单易懂的 Markdown 使用说明。记录实际使用的模板/提示词版本。验证输入校验、跨用户和跨范围拒绝、失败与重试；流程模块还验证同实例 Web→对话续办、重新登录、多人交接、重复请求、旧版本冲突及分支不重放正式动作。

服务或模型不可用时说明真实错误，不用预制结果代替。合成数据不称为真实业务接入。正式浏览器检查使用生产构建，不能以组件单测代替。各仓库完成本地中文规范提交，不提交密钥、运行数据或日志，不自动推送；公共框架改动按统一维护流程协调。


## 状态与调试

先读 docs/通用框架架构与代码地图.md 和 docs/模块开发与调试说明书.md。workflow.state_machine 描述后端真实业务状态；不要与个人 cursor、Run 状态混淆。用 /#devtools 检查注册、声明与本人实例的实时状态，再用 framework-lab 验证双端组件。调试台观察不等于完整事件审计，不直接改业务状态。迁移使用 scripts/export_framework.py 的新源码包，随包重建提示词，凭据与运行数据重新配置。
# 注册验收要求

远程模块还需交付 registration 1.0 声明与握手。使用最新模板的 registration.json 和实际处理函数表，按 docs/模块框架说明.md 完成适配。离线 check 后，在平台发现、安装所需呈现、注册权限，再运行七项接入检查；全部通过后才能发布。不要把发现或健康成功当作接入完成。实际用户授权和完整业务验收仍需另外完成。
