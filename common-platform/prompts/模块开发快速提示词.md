## 先准备，再实现

1. 阅读同批 `docs/模块模板使用手册.md`、`templates/module-kit/` 和 `scripts/module_kit.py --help`。需要精确协议时查询同指纹的 `模块开发与改造提示词.md`、`组件开发提示词.md` 及框架契约。没有模板包或目标框架时说明缺项，不虚构已完成接入。
2. 一次输入得到结果，选择简单工具；有正式对象、多人办理或长期状态，选择流程业务。使用当前工具支持的组合生成新目录，或按手册适配已有服务；不为适应参考示例而重写已有专业算法。
3. 主要实现四项：业务对象、业务动作与状态、职责和范围、共享界面组件。页面组合组件，对话按步骤呈现相同组件，调用同一业务后端。后端以可信仓储事实检查对象权限，不能只隐藏按钮。
4. 使用模板 SDK 接入框架身份与授权，保持当前 manifest、invoke、workflow 和 access 契约。模块角色不塞进固定 actor.roles；安装定义不自动给真实用户授权；服务端凭据不代替用户业务权限。
5. 完成模板的只读静态检查、独立运行及实际业务测试，再在受控宿主验证固定页面和对话。静态检查不执行供应商业务代码；生成包或 HTTP 200 不代表已经接入，每项操作需要核对真实结果和状态。

## 哪些交给框架

模块需要 AI 时，使用同批 `registration.ai_services`、Python/Node AIServiceManager 和 `contracts/ai/v1/`。模块自有 API 私密配置与平台模型配置分开；管理员在主框架按服务显式选择连接来源，不自动 fallback。当前权限、来源修订与模型结果的领域校验仍须逐次核对，具体见 `docs/模块AI服务与配置.md`。

需要跨模块读取固定来源时，使用可选 `source-reads-1.0` 及同批 server-only SDK：平台用当前真实用户重新授权源对象，目标票据不转给上游，来源凭据不进入业务输入或存储。来源对象必须登记只读 query，模块仍检查业务类别、版本、用途和合法字段；没有该可选功能时明确拒绝，不伪造源权限。

统一登录、授权管理、对话记录、私人实例恢复和分支、能力执行入口、共享组件宿主、服务注册和健康检测由框架负责。模块负责实际业务、正式对象、可信归属、并发修订、幂等和专业处理。

当前没有完整游客模式、自助注册、独立站点 SSO、受限授权委派或持久参与者通知。遇到需要这些能力的业务，明确提出公共扩展，不自行另造一套，也不写假字段宣称已经支持。
