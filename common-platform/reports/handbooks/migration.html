框架迁移与 AI 交接指南

本独立项目的维护入口

本次迁入本对话自动创建的项目根目录，根 README.md 和 AGENTS.md 是人和 AI 的入口，根目录的 .git 维护整个 common-platform 子目录，不另建嵌套仓库。必须保留 common-platform 层，说明书生成以其父目录解析受控来源。work/ 放临时检查、缓存、日志和隔离测试，outputs/ 放验收记录与截图。

独立实例默认运行在 http://127.0.0.1:8030/，数据与身份位于本项目 common-platform/data/。原项目和 8020 服务不得作为依赖或停止对象。基础 Python 创建新的 .venv，不启用 system-site-packages；Node24 从锁文件安装新的 node_modules。测试使用预先创建的 basetemp 父目录和独立 PLATFORM_DATA_DIR，不写入运行数据或原用户数据。沙箱如拒绝网络/socket，按权限机制执行同一安装/测试，不复用原项目依赖。

Vite 开发代理读取服务端环境变量 PLATFORM_BACKEND_URL，默认 http://127.0.0.1:8030；启动开发服务前可显式设置它。生产静态页由本后端同源提供。新增模块的中央授权回调也必须连接本实例。

浏览器 Cookie 按主机和路径隔离，不按端口隔离。本项目使用独立名称 common_framework_session，避免覆盖原实例登录；数据目录中的会话与身份也完全独立。

迁移包 SHA256 为 f466aad9dd073a84d64f7c743a7208ef90ea7d30adfee071e1f2d41ce9a9a448，首次解压后的 232 项文件散列已全部核验。根 EXPORT-MANIFEST.json 是原始导入清单，后续修改由本地 Git 追踪，不重写清单冒充原包。完整本轮测试数字、运行身份、浏览器轨迹和截图见根 outputs/独立部署验收记录.md；下方来源历史记录仅说明导出来源。

每轮修改均复核语义、重建提示词及契约快照、执行一致性检查、相关回归、说明书和生产构建；涉及两端宿主时实际浏览器复核。中文规范 commit，不自动推送。无需模型的确定性入口为 /flow framework-lab.workflow 或“打开通用工作项实验室”。中性单用户演示不能等同生产多角色审批，真实外部 LLM 是否已测以本轮验收记录为准。

迁移的是一套独立的通用开发基座。它带主框架源码、模块模板、契约、开发提示词、三份说明书和 framework-lab 中立模块；现有行业模块、业务数据和远程连接留在原工作区。

解压迁移包后，先看 START-HERE.md，然后进入 common-platform/。

docs/模块开发与调试说明书.md 模块形态、状态声明、调试操作和验收
prompts/模块开发快速提示词.md 给新对话/开发 AI 的简明入口

新机器准备与启动

参考环境是 Windows、Python 3.12、Node.js 24。锁定依赖在 requirements.lock.txt 和 web/package-lock.json。不要复制原机器的 .venv 或 node_modules；不要在无依据的情况下升级全部依赖。

在解压后的 common-platform 中执行：

powershell -ExecutionPolicy Bypass -File scripts/setup.ps1
.\.venv\Scripts\python.exe scripts/build_module_developer_prompt.py --check
.\.venv\Scripts\python.exe scripts/build_handbooks.py --check
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Port 8030

如果系统有多个 Node/Python，可通过 setup.ps1 的 -Python、-Node、-Npm 指定可执行文件路径。模板里的 Node 独立服务使用 Node 24；仅满足前端 Vite 最低版本不一定满足该模板。端口占用时使用其他端口，不停止无关进程。

默认访问 http://127.0.0.1:8030/。本地演示初始化账号为 admin / demo-admin-2026、member / demo-member-2026。它们用于本机开发，正式部署前应更换密码并采用明确的身份初始化方案。迁移包不包含原项目的随机账号密码。

默认首页和 /#guide 是四步交互式入门指南，无需登录。里面的分享会练习只保存在当前浏览器，不调用业务接口；源码与练习回归测试随迁移包携带。点击“打开工作台”进入 /#flows 并登录后，依次检查：模块管理中的 framework-lab → 固定流程 → 对话 → 调试台。模型设置为空是正常的，原有密钥没有迁移；先通过确定性流程验收，再按需要在模型配置页面重新设置。

阅读 /#developer-guide 的“框架全貌”，七章保留整体结构、执行与规则，并以“公开与组织”分析模块公开行为、数据和接口后的组合能力。源码包附带 docs/模块公开与业务组织分析.md、隔离边界测试和演示源文件；不把浏览器组合示意称为已实现的组合执行器。正式业务从登录后的工作台验收。

停止服务用 scripts/stop.ps1。指定过 -DataDirectory 的实例，停止时也提供同一目录。脚本根据项目路径、进程参数和创建时间校验身份，不按端口批量结束进程。

迁移包内的安装状态

extensions/installed.json 只启用 framework-lab，flows/installed.json 只装 framework-lab 流程，独立 interaction 包清单为空。没有业务远程连接、行业演示账号、旧数据和原项目报告。

基础角色只保留 member、admin、system_admin。契约里的旧角色枚举仍保留用于协议兼容，不会生成这些业务账号或授权。模块业务角色应通过 access-definition 及范围 grant 注册，不继续扩展平台硬编码角色。

原有通用资源/复核接口属于兼容能力，保留在核心中。当前建议的新模块路径是 capability + workflow/interaction + object adapter + access v1。迁移并不承诺自动转换任意旧数据库或旧前端页面。

自己重新导出

在已完成验证的原平台源码目录运行，输出必须是尚不存在的新目录：

.\.venv\Scripts\python.exe scripts/export_framework.py --output ..\exports\framework-core-new

脚本使用正向源码清单，只读取约定目录与扩展名；拒绝链接来源及覆盖已有输出。导出时生成新安装清单和基础身份策略，重新生成提示词和对应指纹，并渲染通用说明书。依赖、运行配置、前端 dist、模型凭据、数据库、上传文件、日志和 Git 历史均不复制。输出为展开目录与同名 ZIP，附文件摘要。

导出过程中若校验失败，保留未完成目录供检查；换一个新输出目录重试，不把半成品交付为完整迁移包。生成 ZIP 和文件摘要证明打包内容一致，不代替新环境安装和运行测试。

新对话可直接使用的交接提示

你正在维护 common-platform 通用主框架与模块框架。
先阅读 AGENTS.md、docs/通用框架架构与代码地图.md、
docs/模块开发与调试说明书.md、prompts/README.md 和最新开发提示词。
先检查 Git 状态和契约快照；不要假定旧对话中的地址、进程或凭据仍有效。

业务状态以模块仓库的 projection.state 为事实；个人 cursor 和 Run 状态分别处理。
Web 与对话复用共享组件与同一个对象 adapter，不再开发第二套业务流程。
模块声明能力、流程、状态机、权限和办理视图；安装定义不等于给用户授权。
调试台只观察当前管理账号自己的实例，状态图不直接写入业务状态。

先跑 framework-lab 的确定性双端演练，再开发新业务模块。
优先使用 module_kit 模板，Python 原生与 Node/Python HTTP 服务按相同契约接入。
日常业务改动在模块内部；公共协议变更需要同步模板、测试、提示词与说明书。
交付前执行提示词生成与一致性检查、相关测试和生产构建后的真实浏览器测试。
每轮完成后中文规范 commit，不提交密钥、数据、依赖，不自动推送。
把实际完成与尚未支持的能力分开说明，不以接口存在代替端到端验收。

给人交接时讲清楚四件事

  1. 主框架提供“共同的工作场所”：身份、对话、页面、权限、任务和调试。
  2. 模块交付“可组合的零件”：能力、共享组件、对象与流程声明。
  3. 模块后端掌握“业务事实”：数据归属、状态转移、修订和允许动作。
  4. Web 与对话是两种操作入口：共用组件和业务对象，不会因为换入口就产生第二份数据。

迁移验收清单

先校验 EXPORT-MANIFEST 中的文件摘要，再安装锁定依赖并构建 Web。执行包内相关后端测试、前端测试和提示词一致性检查。随后实际完成创建→提交→退回→重提→完成，跨页面和对话继续办理，刷新后恢复，检查调试状态与记录一致。

本项目在包含 common-platform/ 的独立根初始化 Git 仓库，做中文初始提交。业务服务可独立仓库，安装到主框架的声明/组件以可追溯版本交付。不要把旧项目 .git 复制过来造成边界混淆。

若还需要旧项目业务数据迁移，应单独设计数据、附件、账号映射和凭据重建方案；通用源码导出并未执行这些操作。
